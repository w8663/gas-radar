# gas-radar · 多链 Gas 观察台

回答一个很实际的问题：**现在发交易贵不贵？什么时候便宜？**

大多数「gas 查询」只给你**当前这一个瞬间**的数字 —— 它每分钟都在跳，看到 5 gwei 就赶紧发，
两分钟后可能就变成 30 gwei。这个工具换个做法：**按最近 24 小时逐块抽样**，
画出每条链的拥堵曲线，然后告诉你哪个时间窗相对便宜。

## 它做什么

- 对每条链并发抓取最近 24 小时内均匀分布的 N 个区块（默认 36 个）
- 逐块读 `gasUsed / gasLimit / baseFeePerGas / 区块时间 / 交易数`
- 算出：当前 gas、24 小时平均利用率、利用率峰值、平均每块交易数
- 按**你所在时区**聚合出「最便宜的时段」排名
- 判断现在比 24 小时均值贵还是便宜
- 输出 `output/report.md`（人看）+ `output/gas.json`（机器读）

支持以太坊 / BNB Chain / Base / Arbitrum One，全部只用**公开 RPC 的只读调用**。

## 快速开始

```bash
git clone <this-repo>
cd gas-radar

python3 radar.py                                   # 四条链全查
python3 radar.py --chains ethereum,bsc --samples 48
python3 radar.py --tz 8                            # 展示用 UTC+8（北京时间）

cat output/report.md
```

零依赖，只用 Python 标准库，Python 3.8+。不需要 API key，不需要 `pip install`。

## 输出长什么样

```
→ 采样 以太坊 ...
  当前 0.0880 gwei · 24h 利用率 52.4% · 判据=区块利用率 · 正常（利用率 与 24 小时均值相当）
→ 采样 BNB Chain ...
  当前 0.0500 gwei · 24h 利用率 31.6% · 判据=区块利用率 · 便宜（利用率 比 24 小时均值低 29%）
→ 采样 Arbitrum One ...
  当前 0.0200 gwei · 24h 利用率 0.0% · 判据=gas price · 正常（gas price 与 24 小时均值相当）

```

报告里的结论表：

| 链 | 当前 gas | 24h 均价 | 判据 | 现在 | 最便宜的时段（当地） |
|---|---|---|---|---|---|
| 以太坊 | 0.088 gwei | 0.947 gwei | 区块利用率 | 正常 | 08:00（13.6%）、18:00（28.4%）、11:00（37.1%） |
| BNB Chain | 0.050 gwei | 0.050 gwei | 区块利用率 | 便宜 | 00:00（14.5%）、05:00（17.2%）、02:00（19.0%） |
| Base | 0.006 gwei | 0.005 gwei | 区块利用率 | 便宜 | 17:00（5.9%）、15:00（6.5%）、06:00（8.0%） |
| Arbitrum One | 0.020 gwei | 0.020 gwei | gas price | 正常 | 全天无差异（随时可发） |

## 一个真实的坑（这工具存在的意义之一）

**「区块利用率」不能无脑用在所有链上 —— 用错了会得出完全错误的结论。**

Arbitrum One 的区块 `gasLimit` 返回的是 `1125899906842624`（≈ 2^50，一个哨兵值），
不是真实容量。于是 `gasUsed / gasLimit` 恒等于 **0.0%**：

```
#510264074 gasUsed 541484   gasLimit 1125899906842624 txs 5   → 利用率 0.00%
```

如果直接拿它做拥堵判断，会算出「Arbitrum 随时都空得不能再空、随便挑个时段就是 -77%」
这种**看起来很像机会、实际毫无意义**的结论。

所以这个工具会自动识别这种情况：

1. `gasLimit ≥ 10^15` → 判定为哨兵值，利用率不可用
2. 24 小时平均利用率 < 2% → 判定该链长期空旷，利用率不再是有效信号
3. 两种情况都**自动退回用 gas price 做时段对比**，并在报告里写明为什么
4. 如果连 gas price 在 24 小时内都没有变化（Arbitrum 就是 0.0200–0.0203 gwei），
   它会直接告诉你 **「不存在便宜时段，随时可发」** —— 而不是硬编一张假的排名表出来

判定结果都写在报告的「判据」一列，不会让你在不知情的情况下读错指标。

## 可靠性

- 每条链配多个公开 RPC 节点，失败自动切换 + 重试，单点挂掉不会让整份报告失败
- 区块抓取用线程池并发（串行抓 36 个块太慢）
- 某条链失败只影响它自己那一节，其余照常输出
- 公开节点会 403 掉默认的 `Python-urllib` UA → 已带正规 UA

## 参数

| 参数 | 说明 |
|---|---|
| `--chains` | 链，逗号分隔：`ethereum` / `bsc` / `base` / `arbitrum`，默认全部 |
| `--samples` | 每条链抽样区块数，默认 36（越大越准，越慢） |
| `--tz` | 展示用 UTC 偏移，默认 `8` |
| `--out` | 输出目录，默认 `output` |
| `--timeout` | 单次 RPC 超时秒数，默认 12 |

```
gas-radar/

```

## 说明

这里给的是**拥堵程度的相对判断**，不是精确手续费报价。
实际手续费 = gas 用量 × gas price，金额还取决于你这笔操作有多复杂
（一次 ERC-20 转账、一次授权、一次 swap 的 gas 用量差好几倍）。
